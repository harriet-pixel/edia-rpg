# 伊迪亞大陸 RPG｜開發計畫書

版本 v1.0｜2026-11-09｜暫稱：伊迪亞大陸 RPG（英文學習奇幻 RPG 網站）

## 0. 如何使用本文件

- 開新對話視窗時，把整份文件貼給 Claude，說明「現在要做第幾階段」即可接手。
- 本文件是規則的唯一依據。與舊對話衝突時，以本文件為準。
- 凡標示「可配置」的數值，一律放在 data/balance.json，程式碼不得寫死，也不得擅自定案。
- 標示「待確認」的項目，請在開工前先決定。

## 1. 專案概述

- 從零建立獨立網站，不沿用低年級 Game EN 的程式碼與儲存資料。
- 對象：高年級學生。
- 核心一句話：答題累積資源，資源換成進度與收藏，收藏讓玩家回頭再玩。
- 設計原則：操作簡單直觀；奇幻 RPG 視覺但低負載（少動畫、少粒子）；支援桌面與手機；Huninn 字型與字級縮放；進度與收藏必須可靠保存。
- 不新增額外貨幣、題目難易度、土地防禦、武器數值或其他複雜系統。

## 2. 遊戲循環

**首次通關（每區一次）**

1. 在冒險舞台擲骰，沿石階前進，遇到旅途探險、機會／命運，或隨機的小怪／大怪。
2. 打怪勝利後三選一抽牌，每次都保證有一張「召喚進度牌」。
3. 召喚進度集滿，魔法陣啟動，召喚 Boss。
4. 首次擊敗 Boss：獲得神獸 ×1、區域碎片 ×10、商店服裝兌換券 ×1，並解鎖下一區。

**通關後（重複探索）**

1. 該區改為資源農場，不再重跑首通劇情。
2. 通用任務道具可向 NPC 換區域碎片；魔法石累積 10 顆可召喚一次 Boss。
3. 重複擊敗 Boss：碎片 ×10，另有一次三選一配件抽卡。

**長線目標**

- 碎片兌換完整人物套裝（約 50 套，男女各一版）。
- 星星購買一般配件，並可購買已解鎖區域的碎片。
- 神獸靠親密度與進化強化。
- 玩家角色靠經驗值升等，領取等級獎勵（見第 12 章）。
- 寶石圖鑑收藏。

## 5. 冒險與遭遇

- 玩家擲骰，角色沿石階前進；石階事件為題目、機會、命運。
- 怪物在正常探索中隨機出現，不需每格顯示怪物圖示。
- Boss 不隨機出現，只由魔法陣召喚。

| 遭遇 | 內容 |
| --- | --- |
| 旅途探險 | 完成英文挑戰，依機率取得寶石（普通／稀有／傳說，機率可配置） |
| 小怪 | 簡單答題戰鬥，勝利後三選一抽牌 |
| 大怪 | 需答對更多題，勝利後三選一抽牌 |
| Boss | 魔法陣召喚，勝利後固定或特殊獎勵 |
| 機會／命運 | 使用者設定的隨機事件，可發星星、區域碎片或其他素材 |

## 6. 題庫與戰鬥

**四種題型**

1. 圖片題：使用者自行點選「答對了」或「下次再試」。
2. 選擇題。
3. 是非題。
4. 填充題：輸入英文，系統自動判定。

**使用範圍**

- 旅途探險：四種題型皆可。
- 小怪、大怪、Boss：只用選擇、是非、填充，絕不出圖片題。

**戰鬥規則**

- 強度由 HP 與需答對題數決定（數值可配置）。
- 答對：怪物 HP 減少。答錯：不造成傷害。
- 神獸技能「破甲之牙」有機率額外減少怪物 1 HP，但玩家至少要答對 ceil(總題數 × 1/3) 題。
- 戰鬥引擎通用：輸入怪物定義，輸出勝敗與神獸額外攻擊。小怪、大怪、Boss 只是資料不同。

**防卡關**

- 冒險首頁偵測可用怪物題數；低於最低門檻（可配置）時，禁止怪物遭遇並提示「請先新增選擇、是非或填充題」。
- 出題器避免短時間重複同一題。

**圖片題補充**
- 圖片題的題幹為選填；只要有圖片即可保存、顯示與作答。其他題型題幹仍為必填。

**題庫資料夾**
- 最多兩層（例如「英文 → Unit1」）。題目可不屬於任何資料夾（顯示為「未分類」）。
- 資料夾只用於整理；怪物可用題數仍計算全部題目。依資料夾選題出題屬未來功能，不在本階段。
- 刪除資料夾不會刪除題目：題目移回上層（頂層則移到「未分類」），有子資料夾時須先處理子資料夾。

**旅途探險圖片檢視器**（規格，於階段 3 實作）
- 觸發：旅途探險遇到圖片題時，點擊圖片開啟全螢幕檢視器（覆蓋層）。怪物戰鬥不出圖片題，不需要此功能。
- 預設：圖片高度符合視窗可用高度（手機要考慮網址列，使用 dvh），置中。
- 按鈕：「符合螢幕寬度」「符合螢幕高度（還原）」「關閉」。
- 縮放：電腦用滑鼠滾輪，以游標位置為中心；手機用雙指縮放。範圍與步進放 balance.json（viewer.minZoom、viewer.maxZoom，起始值 null，建議 1～5 倍）。
- 平移：滑鼠拖曳與單指拖曳；邊界限制，圖片不可被拖到完全離開畫面。
- 關閉：關閉按鈕與 Esc。點擊背景不關閉，避免手機誤觸。
- 不影響答題：檢視器只是覆蓋層，不改變題目狀態、已選答案與探險進度，不寫存檔。開關期間不會觸發作答或跳題。
- 實作：新增 `js/ui/image-viewer.js`，用 CSS transform 與 Pointer Events，不引入函式庫。縮放與平移的計算（符合高度、符合寬度、限制範圍）寫成純函式並以 node 測試。

## 7. 首次通關：召喚進度與魔法陣

**單一進度數字**

- 底層只存一個數字：召喚進度點。
- 劇情開啟或關閉，只是同一個數字的不同呈現方式，進度不會因切換而消失。

| 模式 | 呈現 |
| --- | --- |
| 劇情開啟 | 多段 NPC 劇情，每段有任務道具與需求量；段落門檻為累計值 |
| 劇情關閉 | 直接顯示「魔法石 7／12」 |

- 範例（第一區）：星光印記 ×4、古樹之葉 ×5、月影結晶 ×3，總量 12；門檻為 4／9／12。
- 各區總量與各段內容之後逐步設定（可配置）。
- 段落獎勵以「已領取旗標」防止重複領取。
- 溢出進度（例如 11 點時抽到 +2）：超出部分直接捨棄。
- 進度集滿後，魔法陣啟動，玩家點擊挑戰 Boss。
- Boss 戰敗：魔法陣保持啟動，重新整理頁面後仍保留，可直接重試。
- 首次擊敗 Boss：記錄該區已通關、解鎖下一區、首通進度歸零。
- 「魔法石」一詞有兩個用途：通關前是進度的顯示名稱，通關後是召喚燃料。兩者是不同資料欄位，不會混用。

**魔法陣三態**

| 狀態 | 提示 |
| --- | --- |
| 未啟動 | 顯示進度，例如「召喚進度 7／12」 |
| 已啟動 | 點擊魔法陣挑戰 Boss |
| 已通關 | 顯示魔法石數量，足 10 顆時可再次召喚；另提供「前往其他區域」 |

- 已通關區域的魔法陣必須保留區域切換，玩家不必為了離開而被迫戰鬥。

## 8. 抽牌表（三張牌位置每次洗牌）

| 時機 | 星星 | 進度／任務道具 | 魔法石 | 區域碎片 |
| --- | --- | --- | --- | --- |
| 通關前・小怪 | 1 張 | 2 張（各 ×1） | 劇情關閉時進度牌即魔法石 | 無 |
| 通關前・大怪 | 1 張 | 2 張（×1、×2） | 同上 | 無 |
| 通關後・小怪 | 2 張 | 通用任務道具 1 張（×1） | 無 | 無 |
| 通關後・大怪 | 1 張 | 1 張，為魔法石或通用任務道具（×1 或 ×2） | 見左欄 | 1 張 |

- 通關後大怪的「魔法石／通用任務道具」那張：魔法石 60%、道具 40%；數量 ×1 或 ×2 各半。起始值，放 balance.json，第一區可玩後再調。平均約 11 場大怪可召喚一次 Boss。
- 通關前每場勝利都有進度牌，不會卡關。
- 抽牌結果在顯示牌面之前就存檔；重新整理後看到同一組牌，不重抽、不漏領。
- 劇情關閉時，不掉落無用途的劇情道具，一律以魔法石呈現。
- 各牌的數量與機率之後在設定檔填寫。

## 9. 通關後：重複探索與資源收集

- 首次通關後，該區改為可重複探索，不再重跑多段 NPC 劇情。
- 兩種獨立資源，不會因完成一輪探索而重置：
  - **通用任務道具**：每區只掉落一種，可向該區 NPC 交換區域碎片（交換比例可配置）。
  - **魔法石**：累積 10 顆可召喚一次 Boss。召喚時消耗 10 顆，多餘保留；戰敗可重試，不需再付。

| 遭遇 | 獎勵 |
| --- | --- |
| 小怪 | 三選一抽牌（見第 8 章） |
| 大怪 | 三選一抽牌（見第 8 章） |
| Boss | 當區碎片 ×10，另有一次三張配件牌選一張 |
| 旅途探險 | 依機率發放寶石 |
| 機會／命運 | 依使用者設定的素材結算 |
| NPC | 當區通用任務道具交換當區碎片 |

**Boss 重複挑戰的配件抽卡**

- 勝利後出現三張背面卡牌，只能選一張。
- 點選的當下才從未擁有的一般配件中隨機抽取，不預先安排三件。
- 配件池：髮型、眼睛、衣服、普通寵物。髮型與眼睛權重較高，衣服與普通寵物較低。
- 只會抽到尚未擁有的商品；剩餘類型不同時，依類型權重重新計算。
- 一般配件全部收集完時，跳過抽卡，直接發放星星 ×30。
- 完整人物套裝與神獸不在此獎池中。
- Boss 獎勵一律不套用神獸技能。

## 10. 貨幣、商店與套裝

| 資源 | 用途 |
| --- | --- |
| 星星 | 買一般髮型、眼睛、衣服、普通寵物；買已解鎖區域的碎片（有價格與每日上限，可配置）；神獸進化費用 |
| 區域碎片 | 只用來兌換該區的完整人物套裝 |
| 商店服裝兌換券 | 首通 Boss 取得，免費兌換一件一般商店服裝；不含碎片限定套裝。服裝已全擁有時，保留不扣 |
| 寶石 | 旅途探險取得，用於圖鑑收藏，分普通、稀有、傳說，不與碎片混淆 |
| 經驗值（EXP） | 玩家升等用，只增不減，不能購買或交易，**不算貨幣** |

**完整人物套裝**

- 五區各有一種碎片，每種碎片可兌換多件套裝；總共約 50 套，每套男女各一版。
- 套裝是完整人物透明背景圖，解鎖狀態永久保存，不因換穿而消失。
- 更衣室兩種模式：**自由穿搭**（Basebody + 髮型、眼睛、衣服分層）與**完整套裝**（直接顯示整張圖）。
- 普通寵物與神獸獨立顯示，不包含在套裝圖內。

## 11. 神獸養成

- 五區各有一隻神獸，首次通關獲得。神獸在角色左側，普通寵物在右側，可同時陪伴。
- 不做餵食、飢餓值、裝備強化或神獸經驗。

| 階段 | 親密度上限 | 進化條件 |
| --- | --- | --- |
| 一階 | Lv.2 | 首次通關取得 |
| 二階 | Lv.4 | 親密度 Lv.2 達上限後，花星星進化 |
| 三階 | Lv.5 | 親密度 Lv.4 達上限後，花星星進化 |

- 親密度只有「目前同行的神獸」會累積；每完成一場戰鬥或一次探險 +1 點（點數與各級門檻可配置）。每隻神獸各自保存。
- 每隻神獸有五個專屬好感度事件，達到指定親密度解鎖，可在神獸頁重看。

**三項被動技能**（每隻名稱不同，內容相同，機率隨親密度提高）

| 技能 | 作用範圍 |
| --- | --- |
| 星辰奇蹟 | 小怪、大怪抽到星星牌時，有機率加倍 |
| 破甲之牙 | 戰鬥時有機率額外減少怪物 1 HP；至少保留 ceil(總題數 × 1/3) 題 |
| 聖域眷顧 | 大怪抽到當區碎片牌時，有機率加倍（只對該神獸所屬區域） |

- 神獸技能不套用於商店購買、兌換、Boss 獎勵與升等獎勵。
- 神獸頁顯示目前技能機率、進化條件與未來可達到的機率。

## 12. 玩家角色升等系統（新增）

以下為建議方案，數值皆為起始建議，全部放在 balance.json，開工前請確認「待確認」項目。

**設計目標**

- 給玩家一個穩定可見的成長感，在每次探索與戰鬥後都有回饋。
- 沿用獎勵引擎，不新增貨幣，不影響戰鬥數值，也不鎖區域，避免卡關。

**與其他成長的區別**

| 成長線 | 對象 | 來源 |
| --- | --- | --- |
| 玩家等級 | 玩家角色 | 完成各種遭遇得到 EXP |
| 親密度 | 目前同行神獸 | 戰鬥或探險 +1 |
| 區域進度 | 各區 | 首通召喚進度、通關旗標 |

**EXP 來源**（依「完成事件」給予，不依答對題數，避免亂猜與刷題）

| 事件 | EXP（起始建議） |
| --- | --- |
| 旅途探險完成 | 5 |
| 機會／命運事件完成 | 3 |
| 小怪戰鬥勝利 | 8 |
| 大怪戰鬥勝利 | 15 |
| Boss 首次擊敗 | 50（一次性） |
| Boss 重複擊敗 | 25 |

- 戰敗不給 EXP，也不扣 EXP。
- 是否加每日 EXP 上限：不加。

**等級與門檻**

- 等級無上限。
- 升級所需 EXP 公式：`需求 = 基礎 + 增量 × (目前等級 - 1)`，起始建議 基礎 20、增量 10，可配置。
- 存檔只記「累計 EXP」，等級由門檻推算。這樣日後調整曲線不會破壞存檔。

**升等獎勵**（都走 grant()，與其他獎勵同一發放流程）

| 類型 | 內容（起始建議） |
| --- | --- |
| 每級獎勵 | 星星 ×10 |
| 里程碑（Lv.5／10／15／20／25／30） | 一次三抽一配件牌（沿用 Boss 重複挑戰抽卡，配件全收集完也沿用Boss規則，直接給星星 ×30） |
| 稱號 | 每個里程碑一個稱號，顯示於冒險者檔案。稱號只做 6 個（到 Lv.30），之後沿用最後一個稱號 |

- 升等獎勵不受神獸技能修飾。
- 以「已領取旗標」記錄每級獎勵，不重複發放。
- 一次升多級時，獎勵依序排隊顯示。
- 升等獎勵先存檔、再顯示彈窗；彈窗中途重新整理，不會漏領或重領。
- 若日後調整門檻導致等級上升，未領取的獎勵進入待領取佇列。

**介面**

- 冒險首頁頂部：等級徽章與 EXP 條，只顯示一行。
- 升等彈窗：沿用統一的彈窗元件，不用額外動畫。
- 更多 → 冒險者檔案：等級、EXP、稱號、已領取與下一級獎勵預覽。

**明確不做**：屬性點、技能樹、等級影響題數或機率、等級鎖區域、等級排行榜。

**程式結構**

- 新增 `js/systems/leveling.js`：純函式 `addExp(state, amount)`，回傳新狀態與 `levelUps[]`，不碰 DOM。
- 戰鬥、探險、Boss 等系統只發出事件（events），由 leveling 監聽，不需修改各來源。
- EXP 也可作為獎勵包的欄位之一，由 grant() 發放。

**必要測試**：單次升多級、極高等級計算正確、重複領取、重新整理中斷、門檻調整後存檔相容、EXP 只增不減。

## 13. 技術架構

- 純 HTML、CSS、原生 JavaScript（ES Modules），不用框架與建置工具，直接部署 GitHub Pages。
- 純邏輯與畫面分離：抽牌、戰鬥、進度、升等寫成不碰 DOM 的純函式，用 Node 內建測試驗證。改邏輯只看測試結果，可省 Token。
- 資料驅動：區域、怪物、套裝、神獸、抽牌表、升等表都放 JSON。
- 儲存：小資料用 localStorage，圖片與題庫用 IndexedDB。
- **儲存隔離**：harriet-pixel.github.io 底下所有網站共用同一個瀏覽器來源，因此所有儲存名稱使用專屬前綴 `edia-rpg-v1`，避免與舊網站互相覆蓋。
- 沒有圖檔的項目自動顯示占位圖，可邊做邊上傳。

**資料夾結構**

```
/index.html          外殼與頁面切換（hash 路由）
/css/                tokens.css（顏色、字級）、base.css、components.css
/js/core/            storage、store、config、rng、events
/js/systems/         questions、battle、rewards、progress、inventory、
                     catalog、beasts、story、gems、leveling
/js/ui/              卡牌選擇、彈窗、貨幣列、提示訊息、等級條
/js/pages/           adventure、bank、wardrobe、shop、beasts、gems、profile、settings
/data/               regions、monsters、story、items、outfits、beasts、gems、
                     draw-tables、levels、balance
/assets/             圖檔，統一命名
/tests/              各 system 的邏輯測試
```

## 14. 必須先建立的共用底層

1. **存檔層**（最先做）：版本號與資料遷移；整份存檔可匯出／匯入 JSON；寫入失敗或損毀時降級，不白屏。
2. **設定檔 balance.json**：所有可配置數字（題數、機率、價格、交換比例、親密度、寶石機率、EXP）都在這裡，程式不寫死。balance.json 必須是合法 JSON，不寫註解。尚未決定的數值填 null，說明寫在同層的 _note 字串欄位。程式讀到 null 視為「待設定」，不等於缺 key。
3. **獎勵引擎**：所有來源只產生「獎勵包」，交給同一個 grant() 發放；抽牌表在資料裡，三選一是同一個元件；神獸技能做成獎勵修飾器；抽牌結果在顯示前先存檔。
4. **題庫與出題器**：四種題型統一格式；怪物模式排除圖片題、題數不足回報不可用；避免短時間重複出題。
5. **區域狀態機**：每區統一記錄已解鎖、已通關、召喚進度、劇情已領取、魔法石、通用任務道具、Boss 是否已召喚。首通、通關後、劇情開關只是不同讀法。
6. **目錄與擁有權**：配件、套裝、寵物、神獸都用同一種「物品 + 是否擁有」格式。「未擁有的一般配件」查詢只寫一次，供商店、Boss 抽卡、升等里程碑與兌換券共用。
7. **事件匯流排（events）**：戰鬥、探險等只發出事件，升等與親密度監聽，避免日後回頭修改各來源。

## 16. 美術規劃

**混合方案**

- 預設由 CSS 生成面板、按鈕、彈窗：暖色底、金色細框、小圓角、輕量噪點紋理，零素材也能完整運作，手機不吃力。
- 重點素材由你提供，放入資料夾即自動取代，不用改程式：卡牌（卡背與三種稀有度卡面框）、魔法陣、區域背景、角色、怪物、神獸、套裝。
- 最值得優先投入的是卡牌，因為抽牌是最有儀式感的一刻。
- 視覺方向：深靛藍夜空 + 羊皮紙卡片 + 金色主按鈕；每區有各自的主色。

**素材規格（建議，可調整）**

| 素材 | 尺寸 | 格式 |
| --- | --- | --- |
| 卡牌卡面／卡背 | 600 × 840 | WebP／PNG，透明背景 |
| 區域背景 | 1920 × 1080（主體置中，保留手機裁切安全區） | WebP |
| 完整人物套裝 | 1000 × 1500 | 透明 WebP／PNG |
| 神獸（三階）、怪物、Boss | 800 × 800 | 透明 WebP／PNG |
| 物品與碎片圖示 | 256 × 256 | 透明 PNG |

**命名規則（建議）**

- 套裝：`outfit_r{區}_{編號2位}_{m或f}.webp`，例如 `outfit_r1_03_f.webp`。
- 神獸：`beast_r{區}_s{階段}.webp`；怪物：`mon_r{區}_{small或big或boss}_{編號}.webp`。
- 套裝美術量最大（約 100 張），建議分批：先用占位圖跑通流程，再逐區補圖。

## 17. 與 Codex 的協作原則

1. 一次只規劃與建置一個合理階段。
2. 優先共用底層，不重複開發獎勵、抽卡、存檔或題庫邏輯。
3. Prompt 精簡但完整：功能規則、資料保護、必要測試與驗收條件。
4. 不要求冗長的檢查報告、工作日誌或大量截圖。
5. 視覺修改只附必要的代表性截圖；純邏輯修改以測試結果為主。
6. 不為了省 Token 而省略測試、錯誤處理或資料驗證。
7. 未決定的機率、價格、題數、交換比例，一律保留為可配置項，不擅自定案。
8. 不擅自增加新貨幣、題目難易度、土地防禦、武器數值或額外複雜系統。
9. 每階段完成後，以簡短文字記錄完成內容、測試結果與下一階段依賴。

**Prompt 範本**

```
【階段 N：名稱】
目標：一句話。
依賴：已完成的模組（不要改動）。
規則：條列（引用本計畫書章節）。
資料：需新增的 JSON 欄位與 balance.json 項目。
測試：必要的單元測試與驗收條件。
不做：本階段明確排除的事項。
回報：3 行以內，完成內容、測試結果、下一階段依賴。
```

**與 Claude 的合作流程**（詳見第 20 章）：開新視窗時貼上本文件，說明「現在做階段 N」；Claude 先確認依賴與待確認項目，再產出 Codex Prompt；Codex 完成後把簡短回報貼回來，一起驗收並更新本文件的進度紀錄。

## 18. 風險與防呆

- 沒有可用怪物題目 → 禁止怪物遭遇並提示。
- 首通抽不到進度牌 → 每次必含進度牌。
- 劇情開關造成進度遺失 → 只存單一進度數字。
- 抽牌後重新整理 → 結果先存檔，不重抽、不漏領。
- Boss 戰敗 → 魔法陣保持啟動，重試不再扣魔法石。
- 兌換券無處可用 → 保留不扣。
- 星星買碎片繞過 Boss → 只能買已解鎖區域，並有每日上限。
- 升等獎勵重領 → 以已領取旗標防止，且先存檔再顯示。
- 存檔損毀 → 降級處理與匯出／匯入備份。

## 20. Codex 銜接流程

Codex 不會記得上一個視窗做過什麼，所以進度一律放進專案檔案，不放在對話裡。任何新的 Codex 打開專案，讀完下列檔案就能接手。

**專案內的三個銜接檔案**

| 檔案 | 作用 |
| --- | --- |
| `AGENTS.md`（專案根目錄） | 永久規則，約 40 行，Codex 開工會自動讀 |
| `docs/PLAN.md` | 本計畫書（由線上文件匯出 Markdown），按需讀取指定章節 |
| `docs/PROGRESS.md` | 每階段的完成紀錄，是真正的「銜接記憶」 |

**PROGRESS.md 每階段追加一段（15 行內）**

1. 完成內容。
2. 新增檔案，以及對外函式的名稱與參數（下一階段靠這個接手）。
3. 測試結果。
4. 與計畫書不同的地方。
5. 下一階段要注意的事。

**每階段的固定流程**

1. **在 Claude 這邊**：開新視窗，貼上計畫書和 PROGRESS.md 最新一段，說「現在做階段 N」。Claude 確認依賴與待確認項目後，產出精簡的階段 Prompt（格式見第 17 章）。
2. **開新 Codex**：用下面的開場。

```
你正在開發「伊迪亞大陸 RPG」。
先讀 AGENTS.md、docs/PROGRESS.md，以及 docs/PLAN.md 的第 X、Y 章，其餘章節不用讀。
本次只做【階段 N：名稱】，不要改動前面階段的檔案，除非下面明說。
（貼上 Claude 產出的階段 Prompt）
完成後：1) 跑測試 2) 在 docs/PROGRESS.md 追加本階段紀錄（15 行內）。
```

3. **完成後**：自己開網站試玩，並跑一次 `node --test`。
4. **回報給 Claude**：只貼 PROGRESS 新增的那一段，不貼程式碼。Claude 驗收、更新本文件進度紀錄，必要時調整下一階段 Prompt。
5. **存一次版本**：Git 提交並標記 `stage-N`，出問題可回到上一個穩定點。
